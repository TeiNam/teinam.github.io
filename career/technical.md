## 기술 면접 준비 및 응답 전략

기술 면접(Technical Interview)은 개발자의 핵심 역량을 평가하는 중요한 과정입니다.

단순히 지식을 암기해서 말하는 것이 아니라, **문제를 어떻게 인식하고, 어떤 방식으로 해결해왔는지를 논리적으로 설명하는 능력**이 요구됩니다.

이는 단순한 기술 습득을 넘어 **협업과 문제해결 능력**, **커뮤니케이션 역량**까지 포함하는 평가입니다.

### 면접 전 준비 방법

#### 1. 기술 스택 정리

- 자신이 주력으로 사용한 언어, 프레임워크, 데이터베이스, 클라우드/배포 환경을 중심으로 정리합니다.
- 단순 나열보다는 **직접 구현하거나 기여한 서비스/기능 중심**으로 준비하세요.
- 사이드 프로젝트, 해커톤, 오픈소스, 학교 프로젝트도 의미 있는 포트폴리오가 됩니다.

예시:

| 기술 | 사용 경험 | 숙련도 | 관련 경험 |
| --- | --- | --- | --- |
| Python | 3년 | 상 | 웹 크롤러, Flask API |
| React | 2년 | 중상 | 사내 포털 프론트엔드 개발 |
| PostgreSQL | 1.5년 | 중 | 배치 수집기, 쿼리 튜닝 |

#### 2. 예상 질문 정리

- 프로젝트에서 가장 어려웠던 점은 무엇이었나요?
- 장애를 경험했을 때 어떻게 대응하셨나요?
- 성능 개선을 위해 어떤 시도를 하셨나요?
- RESTful, OOP, Git 전략 등 핵심 개념을 설명할 수 있나요?

> 각 질문에 대해 **자신의 경험을 기반으로 한 구체적인 답변**을 준비하세요. 면접관은 "무엇을 했는가"보다 "왜 그렇게 했는가"를 궁금해합니다.

#### 3. CS 기본 개념 복습

기술 면접에서는 기초적인 컴퓨터 과학 지식이 자주 질문됩니다. 핵심 키워드는 다음과 같습니다:

- **자료구조**: 배열, 스택, 큐, 해시맵, 트리, 그래프
- **알고리즘**: 정렬, 탐색, 시간복잡도 분석
- **네트워크**: TCP/UDP, HTTP 구조, 3-way handshake, HTTPS
- **운영체제**: 프로세스 vs 스레드, 컨텍스트 스위칭, 데드락
- **데이터베이스**: 인덱스, 트랜잭션, 정규화, 조인, Lock

> 복습은 단순 암기보다는 **실제 업무와 연결하여 설명할 수 있는 수준**이 되어야 합니다.

### 답변 전략: STAR 또는 PAR 기법 활용

기술 면접에서는 정답보다 **문제 해결 과정의 논리성과 구조화된 커뮤니케이션**이 더 중요합니다.

#### STAR 기법

- **S (Situation)**: 어떤 상황이었는가?
- **T (Task)**: 당신이 맡은 역할은 무엇이었는가?
- **A (Action)**: 어떤 행동을 했는가? 어떤 접근을 했는가?
- **R (Result)**: 결과는 어땠는가? 수치나 개선 포인트로 설명하면 좋습니다.

#### PAR 기법 (간결형)

- **P (Problem)**: 어떤 문제가 있었는가?
- **A (Action)**: 어떻게 대응했는가?
- **R (Result)**: 어떤 결과를 도출했는가?

#### 예시 답변 (PAR)

> Q. 운영 중인 시스템에 장애가 발생했을 때 어떻게 대응했나요?

- **Problem**: 새롭게 배포한 API에서 DB 커넥션 풀이 고갈되어 전체 서비스 응답 속도가 급격히 느려졌습니다.
- **Action**: 로그를 추적해 커넥션 릭 발생 구간을 파악하고 핫픽스를 적용했습니다. 동시에 커넥션 풀 수를 조정하고, 이후 배포 시 stress test를 사전 자동화하도록 개선했습니다.
- **Result**: 동일 문제는 재발하지 않았으며, 응답 속도가 평균 40% 향상되었습니다.

### 면접 시 유의사항

- 모르면 솔직하게 “모릅니다”라고 말하되, **해당 주제를 어떻게 학습할지에 대한 방향성**을 덧붙이세요. 예: — "처음 듣는 개념이지만, 흥미롭습니다. 꼭 학습해보겠습니다."
- 자신이 **직접 수행하지 않은 일**에 대해 과장해서 말하지 마세요. 면접관은 쉽게 간파할 수 있습니다.
- 코딩 테스트가 없을 경우, **기술 면접이 더욱 깊게 진행**될 수 있습니다. 반대로, 테스트가 있는 경우에는 해당 결과를 기반으로 면접이 이루어질 수 있습니다.
- **협업에 대한 질문**도 꼭 준비하세요. 예: Git 전략, 코드 리뷰 경험, 동료와의 갈등 해결 사례 등

### 마무리 질문 예시 (면접관에게 질문하기)

면접 마지막에는 지원자도 질문을 통해 **조직과의 핏(Fit)**을 확인해야 합니다.

- 이 팀에서 사용하는 기술 스택의 가장 큰 과제는 무엇인가요?
- 코드 리뷰는 어떤 방식으로 이루어지나요? 페어 프로그래밍도 하나요?
- 신입/주니어 개발자에게 기대하는 역량은 무엇인가요?
- 개발 문화나 배움의 기회(멘토링, 기술 공유)는 어떤 방식으로 제공되나요?

---

기술 면접은 지식을 검증하는 자리이기도 하지만, **지원자의 태도, 소통 능력, 성장 잠재력**을 함께 보는 자리입니다.

자신의 경험과 역량을 구조화하여 명확하게 전달하는 연습을 충분히 하시기 바랍니다.
